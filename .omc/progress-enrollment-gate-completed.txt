### Bug
After the previous ralph session fixed the event-loop blocking in `_execute_re_enroll` (commit pending), the daemon log on 2026-04-25 13:24 showed two back-to-back re_enroll cycles fired from a single user request. Cause: while re_enroll was recording the owner's voice for *sampling*, the same audio was still being routed through STT → generator → IntentQueue, so the generator interpreted utterances during the recording window as new commands and submitted a duplicate `re_enroll` intent. The user spoke for ~15s during recording, was transcribed mid-window, the generator emitted another "запам'ятай мій голос" intent, ActionWorker queued it, and a second 15s recording fired immediately after the first.

### Fix
Extended the existing `_bot_speaking | _indication_speaking` drop-gates with a new `is_enrollment_active` flag on the `Indication` facade.

1. **`src/indication.py`** (Story US-EG-1):
   - Added `self._enrollment_active: bool = False` to `__init__`
   - Added public `@property is_enrollment_active` returning that flag
   - At the top of `notify()`, before the `_enabled` short-circuit and before the cooldown coalescer, the flag is updated:
     - `kind is REENROLL_RECORDING_START` → True
     - `kind is REENROLL_RECORDING_END` → False
   - This means the gate works even when indication backends are disabled or the kind is in cooldown.

2. **`src/generator.py`** (Story US-EG-2):

### Why this design (vs alternatives)
Picked option (b) "global facade flag read by processors" over option (a) "new IndicationCueFrame-style frame routed through the pipeline". Reasons:
- The recording happens *off-pipeline* (sounddevice direct), so there's no audio frame the cue processor can bracket. Option (a) would require synthesizing a 15s frame solely for this gate.
- The processors already lazy-import `get_indication()` for unrelated `notify()` calls — adding one read for the flag is two extra lines, no new wiring.
- Option (b) updates BEFORE the cooldown/enabled check, making the gate work even with indication backends disabled. Option (a) would tie input gating to backend dispatch, which is wrong.

### Out of scope (deliberately not addressed)
- **Magic-word escape during enrollment** (e.g. "скасуй" cancels). User opted for a full block during the 15s window. Easy to add later by checking transcript text against a small allowlist before applying the gate.
- **Suppress STT itself** during enrollment. Currently STT still runs (small wasted Groq API call per fragment) but downstream work is dropped. Pre-gating audio at the transport layer is technically cleaner but ~5x the wiring.
- **Pre-existing E402 in `src/direct_tools.py:23`** (module-level import after another statement) — verified pre-existing via `git stash` round-trip in earlier ralph sessions. Out of scope.

### Learnings
1. **Composing drop-gates is cheap when the pattern already exists.** Adding `_is_enrollment_active()` cost ~10 lines per processor because the `_bot_speaking | _indication_speaking` boolean composition was already there. The hard part was the design decision (flag-on-facade vs frame-in-pipeline), not the wiring.
2. **The flag must update BEFORE the enabled/cooldown checks.** A naive implementation that did the cooldown check first would mean a within-cooldown duplicate START would not flip the flag — a subtle bug that the cooldown unit test caught.
3. **Tests with the real Indication facade are valuable for end-to-end gates.** The integration test in `test_direct_tools.py` constructs a real `Indication` with no backends — `notify()` flips the flag but no audio/visual side-effects fire. This is a good pattern for testing system-wide flag propagation without pulling in a full pipeline.
