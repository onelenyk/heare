### Design decisions / learnings
- Decider is retired (Phase 2.1 generator pipeline replaced it). Plan items targeting decider.py (AWAITING_CONFIRMATION, CONFIRMATION_DEADLINE, CONFIRMATION_TIMED_OUT, MODE_CHANGED, WAKE_WORD_DETECTED) gracefully skipped — IndicationKind enums kept for future revival; wiring left as no-op.
- Added a process-wide singleton (set_indication / get_indication) so producers don't have to thread the facade through every constructor. This was crucial for direct_tools, speaker_namer, mcp_utils, heartbeat — all of which already exist outside pipeline.py construction.
- Thread-safety contract verified by spawning a worker thread in tests/test_indication.py — direct_tools._execute_re_enroll exercises it implicitly when called inside a sounddevice context.
- TTS_FAILURE and AUDIO_DEVICE_LOST deferred (would require deep pipecat hooks not yet exposed by the active code).
- Multi-intent / new-conversation / network-unreachable / speaker-drift T3 events are kind-defined but not actively wired — future work documented in plan §6 Phase D.
- pipecat test fixtures must register submodules as packages (`__path__ = []`) to allow `from pipecat.x.y import Z` traversal in test contexts that use sys.modules patching.
- OutputAudioRawFrame is the only raw-audio frame `transport.output()` actually plays. Bare AudioRawFrame is silently dropped — caught by US-IND-A4a tests asserting subclass.
- IndicationCueFrame inherits from pipecat SystemFrame so pipecat broadcasts it both upstream and downstream; this is what enables decider/generator/SpeakerTagger gating without using BotStartedSpeakingFrame (which would muzzle the user for ~2.5s per beep).
