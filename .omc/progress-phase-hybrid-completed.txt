# Hybrid Tool Execution — Direct vs Claude CLI routing

PRD: .omc/prd.json
Source: user request 2026-04-22
Date: 2026-04-22

## What changed

Implemented smart hybrid routing for tool execution:
- **Simple tools** (bash, read, write, web_fetch, web_search) → `execute_direct()` — fast path
- **Complex tools** (edit, MCP tools) → `claude_cli.call_action()` — reasoning path

The `direct_tools.py` module existed with `execute_direct()` implementation but was never wired in. This phase adds the routing logic in `ActionWorker._process_one()`.

## How it works

```
Intent arrives → ActionWorker._process_one()
                |
                ├─→ _is_simple_tool(tool)?
                |      |
                |      ├─ YES → _execute_direct_path()
                |      |              └─→ execute_direct(tool, args, settings)
                |      |                      └─→ subprocess / filesystem / HTTP
                |      |
                |      └─ NO → _execute_claude_path()
                |                     └─→ claude_cli.call_action(description)
                |                             └─→ Claude reasoning (edit, MCP, etc.)
                |
                └─→ on_result(intent, summary) or on_error(intent, exc)
```

## Performance impact

- **Simple tools**: Bypass Claude API call entirely — subprocess/file/HTTP directly
- **Complex tools**: Unchanged — still use Claude CLI for reasoning
- **80/20 rule**: Most common operations (bash, read, write, web fetch/search) are fast-path
