Class `OpenRouterTopicExtractorCLI(api_key, model, timeout, *, transport=None)` with `async extract_topics(prompt) -> list[str]`. Logger `heare.openrouter_topic_extractor`. ### Design decisions (from the consensus loop)
1. **No `response_format: json_object`.** Resolved Open Question #2. Some providers force a top-level object when this flag is set, which conflicts with the prompt that asks for a bare JSON array. The defensive parser (`_extract_first_json_array`) handles malformed output instead.
2. **Consecutive-failure WARN log.** Architect-required addition. Without it, OpenRouter outages produce silent `[]` topics for every turn. Counter increments on any failure path, resets on success, fires WARN at threshold 3.
3. **Sidestep, don't fix, the latent Claude-path bug.** Critic identified that `parse_decider_response` rejects bare JSON arrays as "not a dict", causing the existing Claude path to silently return `[]` for valid inputs in some cases. This plan does NOT fix that — it routes around it. Tracked as a follow-up.
4. **Dual-backend, default-safe.** New backend is opt-in via config flag. Default on `main` after merge: still Claude. Flip to OpenRouter is a separate follow-up after manual production validation.
5. **Separate non-streaming module.** Did not extend `OpenRouterCLI` (which is streaming-only). Mixing streaming and non-streaming in one class would violate separation of concerns.

### Learnings
1. **Always verify the target before planning.** The first ralplan iteration produced a fully-formed plan that targeted a code path with zero production callers. The Architect's grep-based verification of `create_decider_processor` callers caught it. The premise of any plan must be evidence-checked, not inferred from project documentation (which can drift behind reality).
2. **`docs/full_flow.md` is stale on this branch.** It describes a two-stage decider→generator architecture that was retired in Phase 2.1. Future planning should treat it as historical context, not authoritative.
3. **Consensus mode catches premise errors.** Both Architect and Critic independently flagged the dead-code issue. A single-reviewer workflow likely would have approved the original plan.
4. **`httpx.MockTransport` is the right test pattern for HTTP clients in this codebase** — `OpenRouterCLI` already used it via the `transport=` kwarg, and the new module mirrored that contract for parity.
