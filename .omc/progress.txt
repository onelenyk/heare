### RT-002: Decider fire-and-forget emit queue + 12 state-transition sites
- src/decider.py: imports `EventKind` from .storage; adds `_EMIT_QUEUE_SIZE = 256` module constant (rationale: 10s action ~20 stdout + ~12 transitions = ~32 events, 8x headroom)
- DeciderProcessor.__init__ now constructs self._emit_queue (asyncio.Queue maxsize=256), self._emit_drop_count=0, self._emit_drainer_task=None
- New methods: _safe_emit (sync put_nowait with drop counter + WARNING once per 10 drops), _ensure_drainer (lazy task start if loop is running), _drain_events (infinite loop awaiting queue.get() + store.log_event, catches all exceptions and continues), shutdown (cancel drainer with 100ms wait_for grace)
- 12 emit sites wired:
  - _handle_listening: decider.start (before call_decider), decider.done (after log_decision), decider.dropped_low_conf (in confidence-floor branch), action.armed (in d_type=='act' branch)
  - _handle_confirmation: action.confirmed (yes), action.cancelled (no), action.reprompt (unclear)
  - _execute_pending: action.executing (after state=EXECUTING), action.call_start (before call_action), action.done (try branch), action.error (except branch), state.listening (finally)
  - _cancel_pending: state.listening added for completeness (since it also transitions to LISTENING)
- Principle 3 (fail-safe) verified: test_safe_emit_under_lock_is_fast measures 50 enqueues inside `async with self._lock` complete in <50ms total (well under 1ms each)
- tests/test_decider.py: +9 tests for RT-002 (queue overflow, drainer store-failure survival, lock timing, drainer cleanup, emit sequence for act-yes/act-no/act-error/dropped_low_conf) plus the RT-005 import canary

- Key learning 1: `_ensure_drainer` must call `asyncio.get_running_loop()` and gracefully return if no loop — otherwise unit tests constructing DeciderProcessor outside an event loop would crash. In practice the first _safe_emit happens inside an async test function so this works.

### RT-003: ClaudeCLI._run streaming refactor + action.stdout emission
- src/claude_cli.py: _run gains on_line callback param; replaces proc.communicate() with await asyncio.wait_for(self._read_streams(proc, on_line), timeout=self.timeout)
- New _read_streams method: concurrent drain_stdout + drain_stderr inner coroutines via asyncio.gather, then proc.wait(), returns stripped (stdout, stderr) tuple for backward-compat with _log_invocation
- drain_stdout uses proc.stdout.readline() in a loop; catches asyncio.LimitOverrunError and falls back to proc.stdout.read(8192); splits decoded bytes on BOTH \r AND \n via .replace("\r","\n").split("\n") so progress-bar tools (pytest -v, pip, npm) render as visible motion; invokes on_line per non-empty segment in try/except that logs WARNING on callback exceptions
- call_action plumbed with on_line kwarg to _run; call_decider unchanged (no streaming for JSON decider output)
- src/decider.py _execute_pending: closure _stdout_emit calls self._safe_emit(ACTION_STDOUT, decision_id, payload={'line': line[:8192]}) and passes it to call_action(on_line=_stdout_emit); 8KB line cap protects the queue from runaway single lines
- tests/test_claude_cli.py: rewrote _make_mock_proc helper to support BOTH legacy communicate() path AND readline path. Critical pattern: side_effect=list exhausts on retry reuse (StopAsyncIteration), so switched to cursor-closure async function that returns b'' forever after exhausting the queue. Test test_run_timeout_kills_process: asyncio.sleep is globally patched by existing fixtures so sleep-based hangs return instantly; use asyncio.Event().wait() instead which routes through loop.create_future, unaffected by sleep patching
- +5 RT-003 claude_cli tests: streams_stdout_via_on_line (3 newline-separated lines), splits_on_cr_for_progress_bars ('a\rb\rc\n' -> 3 segments), call_action_plumbs_on_line (end-to-end via call_action), stderr_drained_in_parallel (both streams), on_line_callback_exception_does_not_break_stream (raising callback doesn't halt reading)
- +1 RT-003 decider test: emits_action_stdout_per_line (fake call_action side_effect invokes on_line 3 times; events table has 3 action.stdout rows with correlated decision_id and JSON payloads)
- Test count: 327 -> 333 (+6), ruff clean, zero regressions
- Key learning: `AsyncMock(side_effect=list)` is unusable for readline mocks that must survive retry reuse — use a cursor-closure that persists across calls and returns EOF sentinel forever. Direct-assignment of async functions is also cleaner than AsyncMock wrapping for tests that want guaranteed behavior.
