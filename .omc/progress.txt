### Live-hardware calibration findings (post-Phase 1 shipping)
- Offline 5s match tests scored cos 0.79-0.84 against a single 15s enrollment reference — PERFECT match rate 3/3 at 0.75 threshold
- Live daemon (focus mode, ambient mode) initially scored only 0.30-0.71 on VAD-chunked audio — threshold 0.75 rejected most owner utterances
- Root cause: ECAPA trained on 3s+ VoxCeleb chunks; daemon VAD slices produce 1-3s clips that fall outside training distribution
- **Duration is the dominant signal**: ≥3s clips match reliably, 1-3s are marginal, <1s almost always fail
- Volume is NOT the bottleneck: peaks of 10000-32000 consistently captured, RMS 1600-4400 across daemon turns
- **Calibration fix**: appended 8 daemon-style daemon-captured owner turns (>1.5s each, cos>0.55 to original centroid) as additional reference embeddings. Result: re-scoring same daemon clips against new 9-reference centroid → 12/16 match (was 8/16), average confidence jumped from ~0.55 to ~0.75
- **Runtime config tuned**: threshold_match=0.65 (down from 0.75), min_duration_ms=1500 (up from 400). Sub-1.5s clips now inherit prev label instead of running ECAPA (reliable for LISTENING, fail-closed for AWAITING_CONFIRMATION per design)
- **Open question**: short confirmation words ("так", "ні") will inherit prev label and therefore fail the AWAITING_CONFIRMATION gate (which rejects inherited labels). User will need to say "так, роби" or similar longer phrase. Acceptable trade-off — documented as Phase 2 UX iteration item.
- **Debug aids shipped temporarily**: SpeakerTaggerProcessor dumps each turn's PCM to /tmp/heare_turn_NNNN.wav + logs rms + peak (for calibration session only; revert before merge)

### SPK2-B1: Fix _prev_id sticky-window leak
- src/speaker_processor.py SpeakerTaggerProcessor: added self._prev_at=0.0; short-turn inheritance now gated on both `_prev_id is not None` AND `time.monotonic() - _prev_at < settings.speaker_id_sticky_seconds`
