## US-WU-01 — implemented (2026-04-25)
- One-line swap: src/generator.py:404 now calls `await self.intent_queue.cancel_active()`
  in place of the synchronous `self.intent_queue.cancel_latest()`. The cancel keyword
  gate now reaches `ActionWorker.cancel_in_flight` (CCS-05b kill paths).
- Deleted notify block: src/generator.py:408-415 manual `Indication.notify(IntentKind.INTENT_CANCELLED, ...)`
  fully removed. Single emit site is `src/actions.py:233` inside `IntentQueue.cancel_active`,
  satisfying EC-1.
- Renamed `cancelled_id` log field: the `[TIMING] generator ... cancelled=...` line at
  src/generator.py:500-508 now emits the literal "yes" / "none" derived from
  `cancelled_anything: bool`; the int-id field was dropped. Added a new
  `[CANCEL FAST-PATH transcript=...]` info log when cancel_active returns True.
- Existing test `test_cancel_keyword_pops_pending_intent` updated to assert the new
  `[CANCEL FAST-PATH]` marker instead of the deleted `[INTENT CANCELLED id=N]` line.
- Three new tests in tests/test_generator.py exercise EC-1:
  * cancel_active is awaited exactly once and the generator does NOT call
    Indication.notify(INTENT_CANCELLED) itself.
  * empty-queue / no-in-flight cancel produces zero INTENT_CANCELLED notifications.
  * cancel keyword still lets the LLM run for a spoken acknowledgement.

  * tests/test_actions.py:36,40,48,50,59 — direct unit tests of cancel_latest itself
  * tests/test_indication_wiring.py:56 — fixture mock for an unrelated test
