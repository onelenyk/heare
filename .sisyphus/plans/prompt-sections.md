## Context

### Current Problem
`render_native_system_prompt()` is a 545-line monolithic function. 200+ lines of static text are inline strings — reply rules, speech style, tool-use loop, narration, routing. The output routing block sits at position ~15 out of ~25 sections, buried between mode instructions and capabilities. In production, LLM ignores tags 98.7% of the time (78/79 responses untagged). The "Reply rules" section at position ~20 says "Plain spoken language. No JSON, no markdown, no bullet characters, no code fences" — directly contradicting the tag format instructions 50 lines earlier.

### Proposed Solution
Extract static text into `prompts/` template files. Create a `prompt_sections.py` registry that defines prompt order explicitly. Dynamic sections (context, mode, output routing, capability hints) stay generated by context builder. Static sections (reply rules, speech style, etc.) loaded from templates. Output routing becomes the LAST rules section. Contradictory "plain spoken language" instruction removed.
