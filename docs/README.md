# Документація heare

Три шари, і кожен знає своє місце.

- **`product/`** — живий план: як heare стає мережею тіл. `README.md`
  (загальний), `brain.md`, `body-desktop.md`, `body-web.md`, `hands.md`,
  `protocol.md`, `setup.md`, `clock.md` (надійність — що робимо зараз). Тут
  правда про **як зараз** і **що далі**.
- **`laws.md`, `vision.md`, `plan.md`, `engine.md`** — навіщо, закони,
  контури двигуна. Не описують код; описують, чого він має триматись.
- **`server.md`, `develop.md`** — heare на Linux і в Docker; як зібрати з
  коду. Для людей, яким замало головного README.
- **`assets/`** — знак для README і сайту (`heare-face.svg`).
- **`archive/`** — усе, що описує минуле. Читати заради **чому**, не заради
  **як**:
  - `2026-09-16/` — асистент місячної давнини;
  - `2026-10-18/` — документи про додаток, що жив у `src/` (його останній
    коміт — тег `legacy-app`).

Джерело правди — код, `tests/heare` і `docs/product/`. Документ, який
дублює код, старіє першим.
