# Перший живий прогін двигуна

20 серпня 2026, 21:01. Усе тут — з логу і бази цієї машини, не з читання
коду.

Двигун писався 18–20 серпня: `intents` (те, що переживає хід),
`situation` (де я в часі), `judge` (чи можна зараз озватись), `notice`
(подія стає наміром), `ask` (вето моделі), `environment` (очі). Три дні
роботи, 1500 зелених тестів.

Перед запуском база сказала таке:

```
останній транскрипт     2026-08-17 00:24
таблиця intents         0 рядків
```

Тобто **жоден із цих трьох днів ніколи не бачив розмови**. Усе, що
перевірялось, перевірялось юніт-тестами і читанням.

Чотири хвилини живого прогону дали шість знахідок. Нижче — усі.

## Що підтвердилось одразу

```
21:01:09  features: aec=on wake=on tools=on roles=on mcp=on memory=on
          persist=on usage=on telemetry=on engine=on watcher=OFF
21:01:09  WARNING resolve_llm: opencode has no key — falling back to deepseek
21:01:09  engine: holding intents between turns
21:01:10  engine: awake (tick 5s)
```

Таблиця перемикачів каже правду. Вибір провайдера, підключений 19-го,
працює і скаржиться вголос замість того, щоб мовчки німіти через
випадаючий список. Двигун тікає.

## 1. Двигун не бачив, що асистент говорить

`Engine(state=getattr(loop, "state", None))` — а поля `state` у
`SpineLoop` ніколи не було, і ніде в `src/` немає жодного
`loop.state = ...`. Об'єкт State живе в демоні, ним обгорнуті STT і
мовлення, віддається він тільки в API.

Отже `state is None`, отже `bot_state = "unknown"`, отже:

```python
@property
def busy_talking(self) -> bool:
    return self.bot_state in ("listening", "thinking", "speaking")
```

завжди `False`. А це перша умова в `judge`:

```python
if situation.busy_talking:
    return Verdict(False, "розмова триває")
```

**Захист «не влізай посеред фрази» не міг спрацювати від дня написання
хребта.**

Провід — половина причини. Друга половина: писар і читач говорять
різними словами. Демон стамить `agent_state` як `idle | talking |
interrupted` (`spine_engine.py`, `_agent`), а читач шукав
`listening | thinking | speaking` — словник двигуна, який видалили 17
серпня. Жодного перетину.

Тест, що це охороняв, параметризувався рівно тими трьома словами, яких
ніхто не пише.

## 2. Він зробив пʼять намірів про завдання тижневої давності

`_notice` читає пʼять останніх завдань і робить наміри з тих, що
завершені. `_seen_jobs` на старті порожній, тому на першому ж тіку:

```
job:27   3 дн тому: Порахуй кількість файлів у робочій теці
job:26   7 дн тому: Inspect this Heare setup and list everything…
job:25   7 дн тому: Create a full-screen canvas widget page…
job:24   7 дн тому: Просте завдання, без рендерингу…
job:23   7 дн тому: Read the file /Users/…/src/frontend/…
```

Текст наміру **сам починається з «7 дн тому»**. Воно знало, що це
тиждень тому, і збиралося сказати.

## 3. Вето моделі спрацювало — і врятувало

Через двадцять хвилин ті самі пʼять рядків у базі мали стан `dropped`:

```
22:25:12  engine: judged not worth saying — 3 дн тому: Порахуй кількість…
22:25:23  engine: judged not worth saying — 7 дн тому: Inspect this Heare…
22:25:39  engine: judged not worth saying — 7 дн тому: Create a full-screen…
22:25:50  engine: judged not worth saying — 7 дн тому: Просте завдання…
22:25:56  engine: judged not worth saying — 7 дн тому: Read the file…
```

Це `ask`, підключений 20 серпня разом із watcher'ом. Ланцюг
`notice → judge → ask → drop` пройшов повністю, уперше, на справжніх
даних — і остання лінія захисту зупинила все пʼять разів поспіль.

Єдина знахідка вечора, де щось спрацювало краще, ніж очікувалось.

## 4. Режими не доходять до агента взагалі

Той самий відсутній `loop.state` забирає й друге поле:

```python
mode = ""
if state is not None:      # ніколи
    mode = state.get("mode", "") or ""
```

`set_mode` чесно валідує, ходить у State API, отримує 200 і відповідає
«Перейшов у режим focus». Значення лягає в базу. Читача немає.

Окремо від проводу, профілі режимів втратили виконавців:

```
17 серпня  src/core/pipeline.py          → нікому глушити TTS   (voice_muted)
19 серпня  src/pipeline/session_state.py → нема що перемикати
19 серпня  src/voice/indication/*        → нікому грати звуки    (sound_policy)
```

`turn_timeout` і `prompt_addendum` до хребта не доїжджали ніколи: він
писався з нуля 14 серпня і не переніс цієї проводки.

`src/agent/modes.py` не потрапив у жодну чистку, бо **не виглядав
мертвим** — його імпортують `api.py`, `spine/tools.py`, `agent/hands.py`.
Тільки імпортують тепер для ролей.

Ролі покривають те саме краще, і причина конкретна: **у ролі є час
життя.** Вона починається на фразу, триває, закінчується на фразу і
лишає документ. Тому завжди є один об'єкт, у якого можна спитати «що
зараз чинне» — `src/spine/main.py:294`, одна точка. Режим часу життя не
має, тому кожен шар мусить сам піти прочитати глобальний прапорець, і
кожен шар, який цього не робить, мовчки не робить нічого.

## 5. Присутність рахується лише за мовленням

```python
@property
def user_is_here(self) -> bool:
    return self.user_silence_s < 300
```

Мовчиш годину і працюєш — двигун вважає, що ти пішов. Саме тому пʼять
намірів простояли годину: `judge` повертав «нікого немає».

Це та сама дірка, через яку watcher не заговорить: він створений для
того, хто мовчки працює.

## 6. Почуте уві сні нікуди не пишеться

```python
if gated and not in_role and (self.wake is not None and not self.wake.accepts(turn)):
    logger.info("asleep — turn not addressed to me: %r", turn[:60])
    continue                    # ← і все
```

`_persist_user_turn` викликається лише в `respond()`, тобто після
воротаря. Не пройшов по імені — репліки не існує ніде, крім рядка в лозі.
За годину слухання в `transcripts` — нуль рядків.

А `src/spine/wake_phrases.py` у докстрінзі стверджує протилежне:

> The gate is on *acting*, not on hearing. Speech is still transcribed
> while asleep, which is what makes "listen and remember, answer when
> asked" possible rather than a contradiction.

Наслідок ширший за вечір: `docs/next.md` починається з тези «heare має
те, чого немає в жодного асистента: **він чув усе**». Не чув. 4 391
репліка в базі — це не записане робоче життя, а вибірка тих разів, коли
воротар спрацював.

## Дрібне, перевірене

* `hearectl start` запускає демон як `"$PYTHON" -m src.main start &` —
  без `nohup`, без `setsid`. Він гине разом із терміналом, хоча
  `make help` обіцяє фон. Не регресія: рядок незмінний із 31 травня.
  Справжній вхід — меню-бар, де демон живе всередині процесу (тому
  `hearectl status` каже «not running», хоча воно працює).
* `make e2e` кличе `python -m src.pipeline.room` — модуль видалено
  17 серпня.
* Стартове привітання каже «Гава на зв'язку», персона представляється
  «Дока». Таблиця омофонів у `wake_phrases.py` зібрана з живих сесій для
  «doka» (`докер`, `доко`, `доку`) і вгадана за столом для «гава»
  (`hava`, `гаваа`).

## Урок

Той самий, що в [README](README.md), тільки гостріший.

Жодна з шести знахідок не видима з коду. Кожен файл чесно описує, що
робить; кожен тест зелений; кожен виклик успішний. Бракує щоразу одного
проводу до того, хто мав це відчути — і саме тому греп, тести й читання
не могли цього знайти, а чотири хвилини роботи знайшли все.

Наслідок для порядку робіт: **жодна наступна фіча не рахується
зробленою, поки не відпрацювала в живому прогоні.** Три дні роботи
пройшли ревʼю і не пройшли першої розмови.

## Виправлено того ж вечора

Усе перевірене живим прогоном, не лише тестами.

* `state` доведений до двигуна; словники писаря й читача зведені в
  `BUSY_STATES` / `QUIET_STATES`; тріпвайр у
  `tests/test_spine_situation.py` читає літерали `_agent("...")` з
  демона і падає, якщо зʼявиться слово, якого двигун не знає.
* `_notice` на першому проході запамʼятовує завершені завдання, але не
  робить із них намірів, якщо вони старші за десять хвилин
  (`STALE_JOB_S`).
* Присутність — тепер «говорив нещодавно **або** за клавіатурою».
  `HIDIdleTime` навмисно поза перемикачем watcher'а: «чи є хтось» — не
  стеження, і має працювати з вимкненим спостереженням. Немає читання —
  лишається `UNKNOWN_IDLE_S`, і присутність рахується по мовленню, як
  раніше. Перевірено: `idle_s = 25.3`, `user_is_here = True`, жодного
  сказаного слова.
* Наміри вміють протухати (`expires_ts` — дзеркало `due_ts`),
  спостереження про середовище живуть 15 хвилин. Міграція лягла на
  справжню базу.
* Три хиби watcher'а: «90 хвилин без перерви» рахувало саму перерву і
  спрацьовувало точно в мить повернення; сліпа вибірка (`app == ""`)
  виглядала як перехід і стирала півтори години накопиченого.

Лишились три речі, і жодна з них не код: чи писати почуте, коли до
асистента не зверталися; що робити з режимами; і чи вмикати watcher.
Усі три — у [next.md](../next.md), фаза 1.
