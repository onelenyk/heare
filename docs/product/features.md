# Фічі: один контракт, багато поверхонь

*23 жовтня 2026. Доповнює [protocol.md](protocol.md) §5, але не змінює
контракт частин.*

Фіча — це не «сторінка» і не «роут». Це невелика здатність мозку, яка має
**живий стан**, **названі дії** і, якщо треба, **налаштування**. Сторінка не
знає жодної фічі на ім'я: вона малює те, що їй віддали.

## Межа

```
brain assembly → Features registry → door /api/features → page
```

- `Feature` живе в `heare-brain/heare/features.py` — це assembly-модуль,
  тому він може знати memory/engine.
- Двері (`api/server.py`) **не імпортують** `heare.features`. Мозок передає
  готовий registry у `build(..., features=...)`, як уже передає `mind`.
- Ядро про фічі не знає. `heare.core` лишається мовою розмови.
- Фіча не малює HTML і не знає про DOM.

## Контракт

```python
class Feature:
    id: str
    title: str
    about: str
    group: str
    order: int
    read: () -> dict
    write: (name: str, value: object) -> Awaitable[None]
```

`read()` повертає:

```json
{
  "state": "ready | off | running | error",
  "note": "останній: 22.10",
  "controls": []
}
```

- `state` — стан фічі, не стан сторінки.
- `note` — один короткий рядок правди; не дублює `about`.
- `controls` — підмножина контролів частин: `toggle`, `slider`, `choice`,
  `text`, `button`, `label`, `log`. `slider` може мати `unit`.
- `items` — окреме поле для того, що читають, а не натискають: подія журналу
  чи знайдений фрагмент. Кожен item — `id`, `at`, `title`, `text`, `meta`;
  сторінка малює їх одним рендерером. Це не контрол.

`write(name, value)` виконує одну названу дію. Невідома дія або погане
значення — `ValueError` (двері віддають 400). Фонова дія не тримає HTTP:
реєстр запускає її, одразу віддає `state: "running"` і повідомляє про
завершення подією.

## API

```http
GET /api/features
```

```json
{
  "groups": [{"id": "memory", "title": "Памʼять", "order": 10}],
  "features": [{
    "id": "review",
    "title": "Щоденний огляд",
    "about": "Читає вчорашню розмову і пропонує факти.",
    "group": "memory",
    "order": 10,
    "state": "ready",
    "note": "останній: 22.10",
    "controls": [
      {"kind": "toggle", "name": "enabled", "label": "увімкнено", "value": true},
      {"kind": "slider", "name": "hour", "label": "година", "value": 4,
       "min": 0, "max": 23, "step": 1, "unit": "год"},
      {"kind": "button", "name": "run", "label": "Оглянути зараз"},
      {"kind": "label", "name": "last", "label": "останній", "value": "22.10"}
    ]
  }]
}
```

```http
POST /api/features/{id}/act
{"name": "run", "value": true}
→ {"ok": true, "feature": {…}}
```

- Невідома фіча → 404; погане значення → 400; несподіваний збій → 500.
- Успішна дія шле SSE `{kind: "feature", id, state}`.
- Фонові дії: `running` → `done`/`error`, без job-ресурсу й відсотків.
- Фічі доступні лише власнику/вікну (типовий guard). Частини не можуть
  викликати `/api/features`.

## Перший зріз

| Фіча | Що показує | Дії |
|---|---|---|
| `review` | останній огляд, увімкнено/ні, година | toggle, hour, `run` |
| `consolidation` | останній прохід | `run` |

Обидві — група `memory`, живуть у вже наявній шухляді ⚙ «Налаштування».
Окремої третьої шухляди немає.

## Правда перед UI

Перш ніж давати кнопку, перевір, що вона не бреше:

- `review_once()` і `consolidate_once()` — спільні для планувальника й
  сторінки, під `asyncio.Lock`; інакше два кліки або планувальник і клік
  роблять одну роботу двічі.
- Ручний огляд **позначає** день (`mark_reviewed`) лише після успіху.
  `review_now()` сам маркера не ставить.
- Планувальник огляду не має вмирати на `review_enabled = false`; він
  чекає й перечитує. Зміна години має бути видна протягом хвилини.
- Пропущений день планувальник доганяє **о годині огляду**, а не одразу після
  старту: рестарт удень не має запускати платний прохід. Хто хоче зараз —
  «Оглянути зараз».
- `Engine` і `Core` зараз знімають `quiet_*`, денний бюджет і
  `context_tokens` при старті. Поки вони не читають це живо, UI для них не
  робимо: це була б кнопка-обманка.
