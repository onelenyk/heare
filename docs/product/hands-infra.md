# Руки й тіла: інфраструктура

*26 жовтня 2026. Борг після Н1–Н2 ([native-hands.md](native-hands.md)) і план,
як його закрити. Мета: **нова плата чи датчик — тривіальна задача**, кілька
плат — як кілька будь-яких частин, руки — надійні й однакові.*

## Де ми (чесно)

Native hands працює: 5/5 фраз про плату йдуть до неї, opencode отримує решту.
Але:

| # | Борг | Чому болить |
|---|---|---|
| Б1 | Види дій (`show`, `light`, `switch`) закодовані **двічі**: у мозку (`server.ACT_KINDS`) і в native hands (`_tools`) | новий датчик = правки в мозку, руках і прошивці |
| Б2 | `read_pin` читає те, що плата **звітувала** раз на секунду, а не питає її | датчик, який міряє на вимогу, так не зробиш; відповіді від частини немає |
| Б3 | Руки бачать лише **першу** плату (`_found`) | дві плати — друга невидима |
| Б4 | **Диспетчер — модель** (`model/delegate.py`): окремий виклик, щоб вирішити, кому справа | +1–2 с на кожну справу; рішення інколи випадкове |
| Б5 | Життя виконавця (взяти справу, крок, дозвіл, стоп, результат) **скопійоване** в обидві руки | вади живуть у двох місцях: холостий цикл у opencode hands досі є |
| Б6 | Клієнт моделі скопійований у native hands, лише протокол OpenAI | з Anthropic native hands не працює |
| Б7 | Немає **стенда**: перевірити руки й плату можна лише наживо | кожна зміна — ризик для живого heare; кілька плат не перевірити без кількох плат |
| Б8 | `continues` не прив'язане до рук, що робили попередню справу | «продовж» може піти не тим рукам |

**Холостий цикл (Б5), просто:** руки питають мозок «є робота?». Якщо мозок
одразу каже «ні» (щойно перезапустився, руки ще не впущені), руки тут же
питають знову — сотні разів на секунду, доки щось не зміниться. У native
hands уже є пауза 1 с; у opencode hands — ні.

## Ідея

```
ЧАСТИНА (плата, датчик, будь-що)            РУКИ (native, cli)
  несе свої СКІЛИ:                             беруть скіли всіх частин
  ім'я, опис, параметри, наслідок              як інструменти: kitchen__temperature
        │  стук: "skills": [...]                    │
        ▼                                           ▼
   МОЗОК: зберігає, перевіряє ФОРМУ, не зміст  ◄── /api/skills
          передає виклик частині й чекає ВІДПОВІДІ  ── /api/skills/call
          РОУТЕР-ФУНКЦІЯ: кому справа (без моделі)
```

### 1. Скіли несе частина (закриває Б1, Б2)

Частина при стукові каже, що вміє, повністю — як інструмент для моделі:

```json
"skills": [
  {"name": "show", "about": "Показати кілька слів на OLED 72×40",
   "params": {"text": {"type": "string"}, "seconds": {"type": "integer"}},
   "effect": "harmless"},
  {"name": "temperature", "about": "Температура в кімнаті, °C",
   "params": {}, "effect": "read"},
  {"name": "pin3", "about": "Пін 3: реле лампи", "params": {"on": {"type": "boolean"}},
   "effect": "change"}
]
```

- **Мозок не знає видів.** Він перевіряє лише форму: ім'я, опис, параметри
  як JSON-схема, `effect` з трьох слів, ліміти розміру. Новий датчик не
  чіпає мозку.
- **Руки не знають видів.** Скіл — це вже інструмент: руки його беруть як є.
- **`effect` — для дозволів:** `read` — вільно; `harmless` (екран, світло) —
  вільно; `change` — через суддю (пряме прохання — сам, інакше питає). Хто
  вирішує, що частина чесна з `effect`: **ти**, коли впускаєш її (на картці
  видно скіли з наслідками). Частина, що змінила скіли, — показується знову.
- **Виклик з відповіддю.** `POST /api/skills/call` → мозок шле частині подію
  `call` з `id` → частина виконує й відповідає `POST /api/skills/<id>` →
  мозок віддає рукам. Таймаут (5 с) — «частина не відповіла». Так працюють і
  датчики, і «прочитати пін» — без звітів раз на секунду.

### 2. Кілька плат (Б3)

- Кожна плата — окрема частина з власним ім'ям (`desk`, `kitchen`): його дає
  сторінка пари, воно ж у pid (`oled-desk@esp32c3-desk`).
- Інструмент у руках — `ім'я__скіл`: `desk__show`, `kitchen__temperature`.
  Опис частини (`about`: «на кухні, біля вікна») — в описі інструмента.
- «Покажи на кухні» модель розрізняє за описом; дві однакові без імен —
  руки питають, яку.

### 3. Роутер — функція, не модель (Б4, Б8)

Замість виклику моделі — правила, по порядку:

1. `continues` → ті руки, що робили попередню справу.
2. Є native hands → **спершу їй**. У неї є інструмент
   `pass_to_cli_hands(task)`: «не моє — віддаю». Вона й так кличе модель,
   тож рішення «моє / не моє» безкоштовне.
3. Native відповіла «передаю» → cli hands, з її формулюванням.
4. Немає native → cli hands. Немає жодних → голос каже, що рук немає.

Роутер — **виконавець-обгортка в мозку** (`Hands`): ядро бачить одного
виконавця і не міняється. Справи для opencode: на ~1 с довше (native каже
«не моє»), справи для тіл — на 1–2 с швидше. Голос пише завдання так, щоб
його зрозуміли без розмови (це вже в описі `delegate`).

### 4. Спільне життя рук (Б5, Б6)

`heare-core` вже має `heare/part.py` — життя будь-якої частини. Поруч —
**`heare/hand.py`**: життя виконавця, одне для всіх рук.

- `hand.live(about, do)` — стук, цикл «взяти справу», пауза на порожньому,
  `Desk` (крок, дозвіл, питання, **стоп**), результат, картка «чекає / роблю».
- Руки пишуть лише `do(task, desk) -> str`. cli hands — агент; native — цикл
  моделі зі скілами.
- **Клієнт моделі** для частин — `heare/talk.py` у `heare-core`: обидва
  протоколи (OpenAI, Anthropic), ті самі налаштування й ключі, що в голосу.
  Пізніше мозок переходить на нього ж: один клієнт.
- Це не порушує правил: `heare-core` — те, що частини вже імпортують; ядро
  (`heare/core/`) не росте.

### 5. Стенд (Б7)

Ізольований, без мережі й без живого heare:

- **Віртуальна плата** (`heare-sim`): частина, що стукає зі скілами, виконує
  виклики й відповідає; конфіг — скільки плат, які датчики, які затримки й
  збої. Дві «плати» — за секунду.
- **Стенд рук** (`make bench`): справжній мозок на тимчасовому `HEARE_HOME`,
  native hands, віртуальні плати, модель-заглушка зі сценарієм. Перевіряє
  повний шлях: справа → роутер → руки → скіл → частина → відповідь → голос.
- **`make eval-route`** — набір фраз зі справжньою моделлю (за бажанням):
  куди пішла справа, скільки часу. Ціль — 100% на наборі, медіана < 3 с для тіл.
- Прошивка: ті самі контракти, що в стенді, — тест `test_link_contract`
  звіряє скіли й виклики плати з тим, що чекає мозок.

## Після І8: картинка (26.10)

Перший скіл, що просить руки перетворити параметр: плата оголошує `image`
з `render: {svg: {to: mono, width: 72, height: 40, as: bitmap}}`; модель пише
SVG, native hands чистять його (нічого ззовні) і малюють `resvg` у пікселі
плати (`heare/pixels.py`), плата лише показує 360 байт. Розмір і форму
каже плата — руки не знають екранів. Наживо: серце, сонце за хмарою,
усмішка — 2,6–3,4 с.

## Чого не робимо

- Не даємо native hands шелу, файлів, інтернету — це cli hands.
- Не робимо мозок знавцем пристроїв: він знає форму скіла, не зміст.
- Не ламаємо сьогоднішню плату: `acts` живе, доки прошивка не перейде (І7).

## Вирішено (26.10)

1. Частина, що змінила скіли (новий чи інший `change`), показується на
   пульті знову — як нова довіра.
2. Дві однакові частини без імен — руки **питають**, яку.
