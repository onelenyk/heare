# Нативні руки: план

*26 жовтня 2026. Друга пара рук: швидкі, без сесії й без агента. Дотягуються
до тіл (панель, реле, датчики) і до простих речей; усе складне — далі,
зовнішнім рукам ([hands.md](hands.md)).*

## Навіщо

26 жовтня агент отримав панель (`8b75211`): показати слова, світло, піни. Але
отримав її **голос** — два нові дієслова (`panel`, `read_pin`) у кожному
ході. Це суперечить напряму: у голосу мало дієслів, усе «назовні» йде через
`delegate`. А через opencode «увімкни лампу» — це 5–20 с, сесія й великий
промпт заради однієї дії.

## Ідея

```
голос ── delegate("увімкни лампу") ──► диспетчер (одна швидка модель)
                                         │
              просте, одна-дві дії ◄─────┴────► план, файли, код, питання
                       │                                 │
               НАТИВНІ РУКИ                       ЗОВНІШНІ РУКИ
          модель голосу + інструменти          opencode / Claude Code
          з умінь частин (acts)                  (як зараз)
                       │                                 │
                       └────────── дії частин ◄──────────┘
                                 (один шлях до тіла)
```

- **Голос** лишається з кількома дієсловами: розмовляє і передає справу.
- **Native hand** — частина-виконавець (`packages/heare-native-hands`). Цикл: модель голосу (та сама, з
  інструментами й швидка) + інструменти, зібрані з того, що оголосили
  частини, + кілька простих власних. Без процесу, без сесії, без файлів і
  шелу. Одна справа — кілька викликів моделі, і готово.
- **Зовнішні руки** — без змін: усе, що потребує плану, питань, коду, файлів.
- **Частини** лише оголошують `acts` і виконують їх (як уже зроблено).

## Рішення

1. **Модель — та сама, що в голосу.** Вміє інструменти й швидка. Окремого
   налаштування немає, доки не знадобиться.
2. **Межа:** нативні — проста справа без сесії, одна-дві дії; зовнішні —
   план, питання, код, файли, довга робота.
3. **Хто обирає — диспетчер, який уже є** (`model/delegate.py`): коли
   виконавців більше одного, він однією моделлю обирає за `about` і пише
   завдання. Нативні руки стають ще одним виконавцем зі своїм `about`.
   Нової маршрутизації не пишемо.
4. **Продовження** (`continues`) іде тим рукам, що робили попередню справу:
   інакше opencode втратить сесію.
5. **Зовнішні руки торкаються тіл через той самий шлях:** окремий канал
   (інструмент MCP або двері мозку) «що вміють частини / зроби дію». Шлях
   до тіла один, дозволи ті самі.
6. **Native hand — частина, як усі** (26.10): пакет `heare-native-hands`, стукає
   як `executor`, бере справи через `/api/executor/*`, вмикається на
   сторінці налаштувань. До інших частин ходить через двері мозку
   `GET/POST /api/acts` — лише впущений виконавець. Модель кличе сама
   (ті самі налаштування й ключі, що в голосу): частина не імпортує мозку.
   Ті самі двері — канал opencode hand у Н3.

## Як частина описує вміння

Зараз частина каже `{"name": "pin3", "kind": "switch"}`. Нативні руки
перетворюють вид на інструмент для моделі:

| вид | інструмент | дозвіл |
|---|---|---|
| `show` | показати слова на N секунд | ні |
| `light` | світло: on / off / blink | ні |
| `switch` | увімкнути / вимкнути | **суддя**: пряме прохання — сам, інакше питає |
| `read` *(новий)* | прочитати значення з того, що частина звітує | ні |

Опис (що це за частина, де стоїть, що підключено до піна) частина дає в
`about` і, пізніше, в імені дії: `pin3` → «лампа» з картки панелі.

## Відкрите

1. ~~Дозвіл на пін~~ — **суддя** (26.10): пряме прохання людини
   («увімкни лампу») виконується одразу, самодіяльність рук — питається.
   Те саме правило, що в opencode hand.
2. **Затримка диспетчера** (погоджено 26.10: спершу міряємо). З двома виконавцями кожна справа = виклик
   диспетчера + виклик рук (~2 с). Якщо це відчутно — нативні руки самі
   стають диспетчером: пробують першими й мають інструмент «передати
   зовнішнім» (один виклик замість двох). Міряємо після Н1.
