# Логи системи: детальний план реалізації

Мета: про будь-яку подію на будь-якій машині можна відповісти «що сталося,
де, коли, чому і що було далі», не заходячи на сервер. Вкладка на пульті лише
показує ці дані; головне тут самі записи.

Номери рядків звірені з кодом на коміті `b1b7c61` (випуск 0.9.1). Перед
роботою їх варто перевірити: вони зсуваються.

## 1. Що є зараз

| Що | Де | Обмеження |

| Рядки логів | `heare-core/heare/logs.py`, `setup()` рядок 50 | лише stderr кожного процесу; мак пише `~/.heare/logs/app-keeper.log`, мозок у контейнері |
| Стискання повторів | `logs.py`, клас `Once` рядок 24 | лише для рядків |

### Знайдені проблеми

1. **Порожня причина.** `part.py:218` пише `%s` винятку, а в таймаутів httpx текст
   порожній. Те саме в `:136`, `:230`, `:270`, `:358`.
2. **Гіпотеза про обриви, поки не доказ.** Потік читається з `read=SILENT_S`, це
   15 с (`part.py:50`, `:198`). Якщо за 15 с не прийшло жодного байта, частина сама
   рве потік. Усі частини падають разом, що схоже і на цю причину, і на мережу.
   Крок 1 має перевірити, чи шле `events` (`server.py:972`) сигнали життя частіше.
3. **Токен в адресі.** `part.py:201` кладе токен у `?token=`. Текст винятку httpx може
   містити URL, тому повний текст винятку без очищення в журнал не можна.
4. **Ядро заповнене до межі.** `core/` має рівно 1605 рядків, межа `CORE_LINES = 1605`
   (`tests/heare/test_dependencies.py:49`). Див. рішення 3.
5. **Закриття heare.app.** Swift-застосунок `apps/mac` у цю схему не входить, поки
   не вирішено питання В2.

## 2. Межі: що чим є

Жодного дублювання: у кожного джерела своє завдання.

| | `State.emit` | Журнал пам'яті | `logs.event` (нове) |
|---|---|---|---|
| Питання | що відбувається зараз | що було в житті людини | як працювала система |
| Читач | сторінка, частини, модель | модель, відновлення, пошук | людина, Claude |
| Де | пам'ять мозку | `memory/journal` | файл процесу → база журналу |
| Строк | до рестарту | назавжди, до «забудь» | 14 / 90 днів |
| Слова людини | так | так | **ні** |
| Машини | лише мозок | лише мозок | усі |

Правила:

- Логи ніколи не впливають на роботу: їх не читає жоден код, що приймає рішення.
- `State.emit` не змінюється. Міст у мозку читає його як звичайний читач і пише
  вибрані події в журнал. Друга паралельна розмітка в `conversation.py` не потрібна.
- `logger.warning` лишається. Міст `logging → logs.event` бере все рівня WARNING і вище.
- Правило двох дотримане: учасників багато (усі частини, мозок, пульт, CLI, Claude),
  тому форма запису живе одним модулем.

### Рішення

1. **Слів людини в журналі немає.** Це заміна області `speech` з попередньої чернетки.
   Вона вимагала б окремого доступу й окремого виконання «забудь»
   (`server.py:1515`). Запис має `chars`, `lang`, `loud_ms`. Шлях репліки на пульті
   показує слова, беручи їх із журналу пам'яті за часом і каналом. Тоді ключ Claude
   слів не бачить узагалі, а щоб показати йому фразу, власник натискає кнопку
   копіювання. Вартість: розбір «почув не те» потребує пульта.
2. **Модуль у `heare-core/heare/logs.py`, не в `core/`.** Лише стандартна бібліотека,
   тож частини вже мають його без нової залежності, а межа ядра не зачеплена.
3. **Номер репліки потребує змін у ядрі.** `Message` (`core/forms.py:26`) не має поля
   для номера, а черга розриває `contextvars`. Потрібне поле `trace: str = ""` і
   передача в `_take`/`_answer`, близько 10 рядків. Межу `CORE_LINES` піднімаємо до
   1620 окремим очевидним рядком у кроці 5, бо це обдумане розширення.

## 3. Запис

```python
# heare-core/heare/logs.py
AREAS = ("link", "http", "turn", "stt", "tts", "model", "tool", "hands",
         "keys", "part", "system")
Level = Literal["trace", "info", "warn", "error"]

@dataclass(frozen=True, slots=True)
class Record:
    id: str            # "{source}/{boot}/{seq}", стабільний для дедуплікації
    at: float          # час запису за годинником процесу
    machine: str
    part: str          # voice, eyes, native-hands, keeper, brain...
    release: str
    pid: int
    area: str
    kind: str          # "link.broke": стабільне англійське ім'я
    level: Level
    trace: str = ""
    span: str = ""
    parent: str = ""
    ms: int | None = None
    outcome: str = ""  # ok, failed, refused, timeout, cancelled
    cause: str = ""    # "ReadTimeout: ..." після scrub
    data: dict[str, str | int | float | bool] = field(default_factory=dict)

def configure(part: str, machine: str, release: str, folder: Path) -> None: ...
def event(kind: str, *, level: Level = "info", **fields) -> None: ...
def why(error: BaseException) -> str: ...      # ніколи не порожній
def scrub(text: str) -> str: ...               # прибирає секрети
def span(kind: str, **fields) -> ContextManager[Span]: ...  # міряє ms, ловить винятки
def count(kind: str, **labels) -> None: ...    # лічильник, скидається раз на 60 с
```

`KINDS: dict[str, tuple[Level, frozenset[str]]]` описує всі дозволені імена й поля.
Невідоме ім'я чи поле у тестах падає, а в роботі поле відкидається й пишеться
`log.unknown`. Запис ніколи не кидає винятку в код, що його викликав.

`why(error)`: `f"{type(error).__name__}: {scrub(str(error))}"`, а для порожнього
тексту лише ім'я типу та `__cause__`. Для `httpx.HTTPStatusError` це статус, без URL.

`scrub` прибирає: `token=...`, `Bearer ...`, `X-Heare-Token`, значення за шаблонами
ключів провайдерів, значення з `keys.sources()` цього процесу.

## 5. Сховище

**Файл процесу.** `~/.heare/logs/events-{part}.jsonl`, ротація на 10 МБ, 5 файлів.
Запис іде одним фоновим потоком через `queue.Queue(maxsize=5000)`, щоб аудіо не чекало
диска. Коли черга повна, найновіше відкидається, а лічильник стає `log.lost`.

**База мозку.** `~/.heare/logs/events.db`, окремий SQLite у WAL-режимі.

```sql
CREATE TABLE events (
  id TEXT PRIMARY KEY, at REAL NOT NULL, got REAL NOT NULL,
  machine TEXT, part TEXT, release TEXT, pid INTEGER,
  area TEXT NOT NULL, kind TEXT NOT NULL, level INTEGER NOT NULL,
  trace TEXT, span TEXT, parent TEXT,
  ms INTEGER, outcome TEXT, cause TEXT, data TEXT
) WITHOUT ROWID;
CREATE INDEX events_at ON events(at DESC);
CREATE INDEX events_area ON events(area, at DESC);
CREATE INDEX events_problem ON events(level, at DESC) WHERE level >= 2;
CREATE INDEX events_trace ON events(trace, at) WHERE trace <> '';
CREATE INDEX events_part ON events(part, at DESC);
CREATE TABLE meta (name TEXT PRIMARY KEY, value TEXT);
```

- Міграції: `PRAGMA user_version`, простий список кроків у `api/logbook.py`.
  База несуттєва, тому за несумісної схеми файл просто відкладається убік, а не
  блокує запуск.
- Зберігання: `every_day` видаляє `level < warn` старші за 14 днів, решту старші за
  90. Межа 500 МБ: понад неї видаляються найстаріші інформаційні записи.
- Запис пачками в окремому потоці; aiohttp-цикл не чекає SQLite.
- Час: `at` від машини, `got` від мозку. Сортуємо за `at`, а різницю понад 5 с
  показуємо на пульті.

**Том і резервна копія.** `docker/brain.Dockerfile:27` оголошує `VOLUME
/home/heare/.heare`, тому `logs/` переживає деплой, якщо Coolify тримає постійний том.
Пам'ять уже його пережила, але назву тому варто звірити на кроці 3 (питання В4).
`backup.py:33` бере лише `memory` і `settings`, тому журнал у резервну копію не
потрапляє без змін. Щоденна копія `~/heare-backup.sh` на міні-ПК могла б брати весь
том: це теж треба перевірити, щоб не роздути її.

## 6. API

Новий модуль `heare-brain/heare/api/logbook.py` (база, запис, запити); маршрути в
`server.py` поруч із `history`, рядок 1592.

**`POST /api/logs`**

- Хто: частини (рядок у `PART_CALLS`, `server.py:385`), `machine@` для keeper: у
  `guard:439` дозволити цей шлях поруч із `/api/bodies`.
- Тіло: `{"records": [...]}`, до 500 записів і 1 МБ; один запис до 16 КБ.
- Відповідь: `{"taken": n, "seen": m, "refused": k}`. Понад межі: 413.
- Дедуплікація: `INSERT OR IGNORE` за `id`, повтор безпечний.
- Мозок сам ставить `part` і `machine` з токена, а не з тіла: чужу частину не підробити.
  Часткове поле `data` проходить `scrub` ще раз.
- Частина кроку: надсилає кожні 5 с або на 200 записів; при збої чекає 5, 10, 20… до
  60 с; позиція (`файл + зсув`) у `~/.heare/logs/.sent-{part}`. Після рестарту дочитує
  хвіст, тому записи процесу, що впав, доходять.
- Надсилання йде окремим клієнтом із таймаутом 10 с, не через `Wire.post`, бо той
  чекає нескінченно.

**`GET /api/logs`**

- Параметри: `since`, `until`, `area`, `part`, `machine`, `level`, `kind`, `trace`,
  `q`, `limit` (до 500, типово 100), `cursor`.
- Відповідь: `{"records": [...], "next": cursor, "lost": n}`.
- Хто: власник і `reader@`. У віддалених вікон дозволити у `_remote_window_may`.
- `q` шукає в `kind`, `cause`, `data` через `LIKE`, бо обсяг малий; повнотекстовий
  пошук додаємо лише за потреби.

**`GET /api/logs/now`**: стан частин, обриви за годину, помилки за годину, останній
запис кожної частини. **`GET /api/logs/stream`**: той самий SSE, що й `events`, лише
нові записи.

**`reader@`.** Новий клас токена в `auth.py` і гілка в `guard`: лише `GET /api/logs*`
і `/health`. Видається кнопкою на пульті, показується один раз, відкликається. Через
Cloudflare Access доступ іде service token, який створює власник.

## 7. Кроки

Оцінки: рядки без тестів і перекладів.

### Крок 1. Причина обриву. Самостійний випуск

- **Збої:** зміна лише тексту запису, поведінка та сама.
- **Тести:** `test_part.py`: порожній виняток дає ім'я типу; URL з токеном очищено.

- **Обсяг:** близько 40 рядків. **Залежність:** немає. **Агент:** один, першим.

### Крок 2. Запис

- **Мета:** кожен процес пише форму з розділу 3 у свій файл.

  50) і в усіх точках входу, що викликають `setup`: мозок, keeper, voice, eyes,

- **Вживу:** перезапуск, файли з'явились, `part.started` є від кожної частини.
- **Власник:** нове «Дозволити». Випуск 0.10.0.
- **Обсяг:** 250 рядків. **Залежність:** крок 1. **Агент:** один, цю форму беруть усі.

### Крок 3. Доставка

- **Мета:** записи всіх машин лежать у мозку й читаються запитом.
- **Файли:** новий `api/logbook.py`; `server.py` маршрути, `PART_CALLS`, `guard`,

- **Сигнатури:** `Logbook(path).add(records, who) -> dict`,

- **Збої:** мозок недоступний — лежить у файлах; база зіпсована — відкласти файл убік,
  створити нову, записати `log.lost`; диск повний — відкидати нове, голос живе.

## 8. Вкладка «Журнал»

```text
┌ Зараз ───────────────────────────────────────────────┐
│ мозок ✓  голос ✓  очі ✓  руки ✓   обриви за годину: 2│
├ [Усе] [Проблеми] [Зв'язок] [Голос] [Модель] [Руки]    │
│ частина ▾  машина ▾  за годину ▾  пошук…   ● наживо  │
├──────────────────────────────────────────────────────┤
│ 21:36:57 ⚠ Зв'язок обірвався · голос, очі, руки  ×3  │
│          ReadTimeout · мовчав 15 с · відновився за 65 с│
│ 21:35:02 ◉ Репліка · 3,2 с · передано рукам · відмова│
└──────────────────────────────────────────────────────┘
```

- **Стани:** завантаження; потік живий; потік розірвано (плашка й дані лишаються);
  порожньо: «Поки нічого. Записи з'являться, щойно частини під'єднаються»; нічого за
  фільтром із кнопкою «Скинути»; немає зв'язку з мозком.
- **Групування:** однакові події в межах 5 с одним рядком з кількістю. Обрив не показує
  три записи.
- **Шлях репліки:** розгортається під рядком як часова смуга кроків, зі словами з журналу
  пам'яті. Найповільніший крок виділено.
- **Сирий запис:** розгортається; там JSON.
- **«Скопіювати для Claude»:** вибрані записи в JSON, без слів, з фільтрами в заголовку.
- **Телефон:** один стовпець, фільтри в ряд із прокруткою лише в них, 16 px поля,
  без горизонтальної прокрутки сторінки.

### Шлях міток

`kind` стабільний і англійський. Сторінка має карту `kind → шаблон`, кожен шаблон
позначений `tr()`, наприклад `tr("Connection broke")`. `make i18n` переносить у каталог,
переклад у `heare.po`. `test_language_rule.py` ловить пропуски. `cause` і `data` не
перекладаються. Claude читає сирі дані.

## 9. Ризики

| Ризик | Що робимо |
|---|---|
| Запис гальмує голос | фонова черга; перевірка `make bench` |
| Витік секрету | `scrub`, дозволені поля, приманка в тестах, повторна перевірка мозком |
| Токен у `?token=` в журналах проксі | не логуємо query; перенесення в заголовок лише окремою зміною |
| Журнал б'є по диску міні-ПК | межа 500 МБ, `system.vitals` |
| Обрив ламає саму доставку | спершу файл, повтор, ідемпотентність |
| Журнал стає залежністю | правило: код його не читає |
| Шум знову ховає головне | фільтр «Проблеми» типово, лічильники, групування |
| Нове «Дозволити» після кожного випуску | об'єднати кроки 4а–4д одним випуском |
| Старі частини проти нового мозку | мозок ігнорує незнайомі поля, частина на 404 чекає |

## 10. Відкриті питання

- **В1.** Рішення 1: журнал без слів людини. Рекомендую так, остаточно затверджує власник.
- **В2.** Чи писати `apps/mac` (Swift) у журнал? Без цього причина закриття застосунку
  лишиться невідомою. Рекомендую малий окремий крок після 4: Swift пише той самий JSONL,
  а `Shipper` keeper його дочитує.
- **В3.** Підняти `CORE_LINES` до 1620? Рекомендую так, бо це єдиний спосіб передати номер.
- **В4.** Назва постійного тому Coolify й обсяг щоденної копії: звірити на міні-ПК на кроці 3.
- **В5.** Строки 14 і 90 днів та межа 500 МБ: типові значення, власник може змінити.
- **В6.** Service token Cloudflare створює власник перед кроком 7.
