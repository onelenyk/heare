# opencode: один транспорт

*15 листопада 2026. Усе виміряно на opencode 1.19.5 робочими пробами: ACP і
HTTP, з git і без, повний хід від «доручи» до «відкоти». Мета — **максимум
можливостей і профіту саме з opencode**, тож переносність між агентами більше
не мета, і платити за неї двічі нема чим.*

## Рішення

1. **Агент один — opencode.** Claude з таблиці ранерів іде: він тягне за собою
   npx-адаптер і умовні гілки, а «будь-який агент — рядок у таблиці» вже
   виявилось фікцією (`_opencode_env`, `_opencode_config`, `ask_tool()` на
   кожного окремо).
2. **Один транспорт — HTTP.** `opencode serve --port <вільний>`; усе, що давав
   ACP, HTTP дає теж, і ще диф, відкат, todo, ціну, назви сесій, `fork`.
   `acp.py` видаляється — не «лишається поруч».
3. **Лише класичний набір `/session/*`** — той, яким користується їхній власний
   TUI. `/api/*` (v2) і `/experimental/*` не чіпаємо: вони вже рухаються
   (`/api/session/{id}/revert/stage` на 1.19.5 віддає 404).
4. **git — субстрат для «що змінилось» і «відкоти».** Без репозиторію `diff`
   порожній, `revert` — нічим. Це модель opencode, не наше обмеження.
5. **Не питаємо двічі.** Дозвіл приходить подією `permission.asked`; відповідь —
   `POST /permission/{id}/reply` зі `once` / `always` / `reject`. `always` — це й
   є «більше про це не питай».

## Власний дім агента (15 листопада)

Наш агент **не живе в домі людини**. Усе його — конфіг, вхід, сесії, моделі —
лежить у `~/.heare/machine/opencode/`:

```
opencode/
  config/   state/   cache/   data/     ← XDG_* сюди
  home/                                 ← HOME сюди
  opencode.json                         ← наш конфіг (переписується)
  config/extra.json                     ← що додала людина (зливається)
```

`HOME` довелося рушити теж, і це виміряно: `~/.opencode/opencode.json` (конфіг
інсталяції) opencode читає **попри** `XDG_CONFIG_HOME` і `OPENCODE_CONFIG_DIR` —
саме звідти в наш агент протікали плагіни людини (`oh-my-openagent`), а з ними й
її MCP-сервери.

**Що переносимо** (інакше кодер не працює): git-особу — `~/.gitconfig`
підключається через `[include]` у нашому `.gitconfig`; ключі ssh — `~/.ssh`
симлінком у наш `HOME`. Агент і раніше міг їх прочитати; тепер ssh їх ще й
знаходить.

**Провайдери.** Три шляхи, усі — в нашому домі:
1. `heare-cli-hands login` — `opencode auth login` з нашим оточенням;
2. картка: base URL + ключ + модель (наш `provider.options.baseURL`);
3. `config/extra.json` — будь-що з конфігу opencode (провайдер, плагіни, MCP).
   Зливається в наш конфіг, **крім** `permission`: підлога під діями лишається
   наша, хоч би що там написано.

**Модель, якої нема в домі**, не валить справу: агент каже про це в журнал і
бере модель сервера (`GET /config/providers` — перевірка перед створенням сесії,
без запуску CLI).

**Після `make live`** агент входить у порожній дім: один раз
`heare-cli-hands login`, далі — як звично. Картка каже це сама.

## Що виміряно (1.19.5)

| Проба | Результат |
|---|---|
| `opencode serve --port N` → `GET /global/health` | `{healthy: true, version: "1.19.5"}` |
| `POST /session` → `POST /session/{id}/prompt_async` | 204; робота йде у фоні, клієнт вільний |
| `GET /event` (SSE) | `message.part.updated`, **`message.part.delta`**, `message.updated`, `session.status`, `session.diff`, `session.idle`, `file.edited` |
| дозвіл | `permission.asked {id, sessionID, permission: "read"\|"edit"\|"bash", patterns, metadata:{filepath, **diff**}, tool:{messageID, callID}}` → `POST /permission/{id}/reply {"reply":"once"}` → `permission.replied`, зміна відбулась |
| `GET /session` / `GET /session/{id}` | `slug`, `title` (авто: «Uppercasing "two" in note.txt»), `cost`, `tokens {input, output, reasoning, cache{read, write}}`, `agent`, `model`, `directory` |
| `GET /session/{id}/diff?messageID=msg_…` | `[{file, patch, additions, deletions, status}]` — готовий диф |
| `POST /session/{id}/revert {messageID}` | файли **повертаються**, `git status` чистий; `unrevert` — назад |
| `GET /session/{id}/todo` | список справ зі статусами — працює й без git |
| `POST /session/{id}/abort` | є; «стоп» не потребує ACP-каналу |
| тека **не** під git | `diff` → `[]`, `summary` → нулі, `revert` — нічого не робить |
| `summary` у `GET /session/{id}` | **не вірити**: після правки показує `{0,0,0}`, а `diff` — `+1/−1`. Рахуємо з `diff`, не з `summary` |
| `POST /api/session/{id}/revert/stage` | 404 на 1.19.5 — не використовувати |

## Стан

**Ф1 зроблено (15 листопада).** `reach/opencode.py` — сервер, стрім, дозволи,
питання, стоп, диф, відкат, todo, ціна; `acp.py` і `bridge.py` видалено (у
opencode є рідний інструмент `question` — міст більше не потрібен), Claude
прибрано з ранера; тести — на `fake_opencode.py` (HTTP), 2024 зелені; «Перевірити»
на картці тепер справді піднімає агента й питає `/global/health` (дим-тест Р3).
Перевірено живим opencode 1.19.5: правка, дозвіл, диф `+1/−1`, назва сесії й
ціна прийшли з нового транспорту.

**Ф2 зроблено (15 листопада).** Після справи руки питають сервер, що змінило
повідомлення (`GET /session/{id}/diff?messageID=…`), і показують картку в чаті
(`changes.card`: рядок на файл, `+/−`, патч у `<pre>`), а до результату додають
одне речення (`changes.said`: «Змінив note.txt: +2 −1.»). Числа рахуються з
дифа, не з `summary`. Тека без git — диф порожній, картки й речення немає, і це
чесно. Картка проходить `timeline.from_part` (тест), сторінка, що не взяла
картку, не валить справу. Живий прогін: `note.txt +2 −1`, картка 235 байт.

**Ф3 зроблено (15 листопада).** «Відкоти» — це дієслово, а не задача для
моделі: мозок ставить у чергу справу з `verb` (`undo`/`redo`), вона йде прямо
тим рукам без роутера й без переписування слів (`Task.verb` → `hand.Job.verb` →
`claim.verb` → `cli_hands._verb`). Руки питають сервер, чи сесія вже відкочена
(`GET /session/{id}` → `revert`), і кажуть правду: «Повернув як було.»,
«Нічого відкочувати.», «Не вдалося повернути як було.». Інструмент у мозку —
`undo` (серед дієслів, які модель зобов'язана кликати, а не вигадувати).
Живий прогін: правка → `undo` повертає файл → другий `undo` каже «нічого» →
`redo` повертає зміну.

**Ф4 зроблено (15 листопада).** «Спершу покажи план» — теж наказ: інструмент
`plan` у мозку ставить справу з `verb="plan"`, руки ведуть той самий хід, але
промптом з `agent: "plan"` — агент, що лише дивиться. Файли не змінюються,
відповідь приходить словами, а «роби» — звичайна справа з `continues` у тій
самій сесії. Руки також читають власний список справ агента
(`GET /session/{id}/todo`) кожні ~2 с і показують його на картці полем «План».
Живий прогін: план не змінив файл, наступна справа змінила.

**Ф5 зроблено (15 листопада).** Два інструменти: `recent_work` питає руки, що
вони робили (`GET /session?directory=` — назва від opencode, час, id), і
`continue_work` веде роботу в названій сесії; `fork: true` — спершу
`POST /session/{id}/fork`, далі робота в гілці. Сесія їде тим самим шляхом, що
й дієслово: `Task.session` → `Job.session` → `claim.session` → `resume`.
Живий прогін: дві справи з різними назвами, `recent` показав обидві,
продовження першої змінило саме її файл, гілка дала нову сесію.

**На картці рук (16 листопада).** Список сесій живий: назва й час кожної, з
власного сервера, оновлюється кожні ~4 с («Сесії агента»). Поруч — вибір
**«Продовжити»**: «остання» або одна зі справ; ним «продовж» із голосу означає
вибрану справу, а не механічно останню. Сесії належать робочій теці: змінив
`executor_cwd` — старі зі списку зникають.

*Межа гілки:* `fork` розгалужує **розмову**, не файли — робоча тека одна. Хто
хоче «а якби інакше» без слідів у теці, тому потрібен git worktree, а це вже
інша річ (і в Р4 вирішено його не робити).

*Не зроблено:* ціна голосом. Картка її показує (`$0.0000 · 17k`), але щоб
відповісти на «скільки коштувало», мозок має читати звіт рук — це наступний
крок, не сьогоднішній.

**Ф6 зроблено частково (15 листопада): `show`.** Міст повернувся — але вже не
саморобним сокетом-замість-ACP, а звичайним MCP-сервером у нашому конфігу
(`mcp: {heare: {type: local, command: [python, -m heare.reach.bridge, --socket …]}}`).
Один інструмент — `show`: картка (html) або посилання, без скриптів і стилів
(мозок їх і так вирізає). `ask` туди **не** повертається: у opencode є рідний
`question`, і два способи спитати — це один зайвий. `heare_show` — у списку
«тільки дивитись», тож агента про картку не питають.

Живий прогін: агент сам побачив `heare_show` і викликав його — руки дістали
`{tool: show, title: Greeting, html: "<h3>Hello</h3>…"}`, міст відповів
«Shown.», агент сказав одне речення.

*Що лишилось і чому це не один рядок:*
- `remember`, `remind`, `speak` — у дверях немає відповідних кінцівок (є лише
  `claim/step/permit/ask/show/result`). Тобто спершу протокол: нові
  `/api/executor/{id}/remember|remind|say`, далі мозок і руки. Це окремий крок.
- **очі → image-блок**: `promptCapabilities.image` є, але частини не говорять
  одна з одною; знімок від `heare-eyes` до рук має провести мозок — ще один
  канал, не сьогоднішній.

## Кодування: що заважало і що вирішено

Живий прогін 15 листопада (зламана функція, падаючий тест): виправлено за 12 с,
7 кроків, агент сам прогнав тест, картка `+1 −1`, «відкоти» повернув файл. Тобто
цикл кодування працює; заважали шість дрібниць. Стан:

| # | Що | Стан |
|---|---|---|
| **А** | робочу теку не видно на картці — правилась лише в `config.toml` | ✅ поле **«Тека»**: приймає лише існуючу теку, `~` розгортається, порожнє = `~/heare-work` |
| **Б** | відповідь була всім транскриптом («I'll look at the files…») | ✅ відповідь — **останнє повідомлення**; транскрипт лишається в подіях для термінала |
| **В** | у дифі сміття: `__pycache__`, `.pyc`, файли з `+/− = 0` | ✅ `changes.relevant` викидає кеші, залежності й порожні зміни; числа й речення — лише з релевантних |
| **Г** | одна справа за раз на машині | **вирішено не змінювати**: друга рука — це друга машина (адреса руки — pid, протокол §4 це вже дозволяє). Черга в руках — складність без потреби |
| **Д** | стеля 30 хв на справу (35 у ядрі) | **вирішено не піднімати**: довга робота продовжується сесією («продовж»), а не одним ходом. Стеля — захист від зависання, не обмеження амбіцій |
| **Е** | ізоляції немає: агент править робочу теку напряму | **відкрите**: Р4 у [hands.md](hands.md) вирішив не робити worktree на задачу. Повертатись — свідоме рішення (worktree на справу = гілка + «а якби інакше» без слідів), не «фікс» |

Ще одне, не з цього списку, але з того ж прогону: **модель одна на всі справи**.
Для правки в рядок і для рефакторингу доцільні різні — це наступний кандидат
(поле `model` у задачі, як `verb` і `session`).

## Відкрите (перевірити в Ф1, не вгадувати)

- **Чи переживає сесія перезапуск сервера.** Сесії лежать у сховищі opencode;
  вбити сервер → підняти → `GET /session/{id}` → чи продовжується розмова.
  Від цього залежить `resume` (заміна `session/resume`).
- **Форма `message.part.delta`** — дельта чи повний текст на кожну подію. Для
  голосу це важливо: перше речення має звучати, поки пишеться друге.
- **`mcp` у конфігу** — точні ключі (`type: "local"`, `command`, `environment`,
  `enabled`) і чи зветься інструмент так само `heare_ask`.
- **Порт і безпека.** `serve` слухає localhost **без ключа**: будь-яка місцева
  програма може керувати агентом. Це ціна; іншого входу opencode не дає.
  `--cors` не вмикаємо, `--mdns` не вмикаємо.
- **Версія.** На старті порівнюємо `version` із `/global/health`; змінилась
  мінорна — кажемо на картці, а не мовчимо.
- **git у робочій теці.** `~/heare-work` — `git init` при першому використанні;
  тека людини — як є: не репозиторій, значить «змін не видно», і це сказано
  вголос.
- **Дефолтна модель.** `MODEL = "deepseek/deepseek-flash"`; якщо її немає —
  кажемо на картці, на чому агент насправді поїхав.
