# Перебудова сторінки: чат-перший UI

*11 листопада 2026. Архітектура розкладена п'ятьма паралельними специфікаціями;
код ще не змінено. Макет: `.sisyphus/ui/sketch/` (живий на `127.0.0.1:9876`).
Живий план сторінки: [../page.md](../page.md).*

## Що вирішено

- **Чат — головне вікно.** Артефакти є повідомленнями; окремої дошки немає.
- **Чат — бордерна панель.** Док пінів — плаваюча бульбашка вгорі, композер —
  плаваюча бульбашка внизу; під обома м'яке затемнення; стрічка прокручується
  під ними.
- **Артефакти:** text, html, image, audio, video, link, ask, step. Широкий
  артефакт займає крила панелі; звичайний текст лишається у колонці.
- **Піни — якорі, не копії.** Слід — піни поточної сесії вище вьюпорта;
  полиця — піни інших сесій. Чип: мініатюра, заголовок, другий рядок; повне
  прев'ю. Видалення сесії прибирає її піни. Одне живе втілення артефакта.
- **Ліве меню — висувна штора:** компактні картки машин + карусель тіла
  (voice, eyes, hands, page, sources; одна частина на сторінку; керування
  всередині; окремої штори налаштувань частини немає) + сесії/пам'ять/
  деталі/налаштування.
- **Пам'ять, деталі, налаштування** мусять зберегти кожен старий факт і
  функцію — див. [sheets-tests.md](sheets-tests.md). Макет спрощує частину
  цих екранів; переносити треба **справжні** шити, а не спрощені з макета.
- **Шапка:** обличчя/фаза/модель/стоп/налаштування + стани мікрофона й звуку
  + остання активність.
- **Мобільне:** чат на всю ширину; одна штора за раз; широке = на всю ширину.

   `#pdrawer` прибрати після того, як їхні функції переїхали.
2. `#hold` (дозволи/питання/кроки) перенести в стрічку, інакше зникнуть живі
   дозволи й кроки роботи.
3. `vars()` перевести з `#stage` на `#chat` або `documentElement` — інакше
   зламається читання кольорів.
4. `make test`, `make lint`, `make i18n`, `make i18n-check`, `make live`;
   перевірити 1440 і 390; `make rollback` як шлях назад.

## Дані, які не можна втратити

- **Джерела пам'яті** в макеті — вигадані перемикачі погоди/курсу/календаря;
  справжня вкладка «Джерела» — імпорт інших інструментів, прогрес, undo,
  кількість імпортованих фактів. Лишаємо справжню, перестиляємо.
- **Копії**: sound, broken, counts, restored, folder, restart polling — не
  викидати.
- **Факти** без confidence і **слух** без truth втрачають видимі дані й цикл
  виправлення.
- **Профіль**: три блоки з окремим Save і серверними лімітами 1200/1000/600,
  а не один Save.
- **Деталі**: справжні prompt bits, usage, машини — не статичні підписи макета.
- **Налаштування**: усі ключі, пристрої, фічі й `controlsFor`, а не вигадані
  чотири перемикачі.
- Старий `canvas.json` не видаляти: копія в повідомлення з маркером
  `canvas.migrated.json`; `remove` = `withdrawn`.

## Паралельність і файли

- Ядро (`page.html`, `page.css`, `page.js`) володіє каркасом, станом,
  хелперами, `?demo=1`. Лінії володіють своїми `ui/*` файлами.
- Усі `ui/*.js` — **classic scripts** після ядра, не модулі й не `defer`:
  `tr`/`I18N` з inline-блоку мусять бути видимі під час розбору.
- Кожен новий файл додається в `PAGES` (мова), екстрактор `make i18n`,
  маршрути `/ui/*` і текстові тести `page.html`/`page.css`/`page.js`.
- Один агент — одна лінія; ядро і злиття — координатор. Це прибирає конфлікти
  одного файла, які інакше неминучі.

- `make live` і `make rollback` перевірені.

## Відкриті питання

- Де живе канвас між F0.3 і F0.4 — у шторі (план) чи одразу першим `.msg.live`?
- Піни — у мозку (`pins.json`, план) чи в сторінці; хто прибирає їх при
  видаленні сесії?
- Чи може людина прибрати повідомлення зі стрічки; що показувати на місці?
- Чи лишається `?demo=1` постійним стендом?
- Чи має текстовий канал окремий слайд, рядок у «Деталях» чи жодної поверхні?
- Чи потрібен окремий `/api/usage`, чи `/api/state` достатньо?
- На широкому екрані ліва штора модальна (вуаль + inert) чи ні (клік по чату
  закриває)?

## Ризики

- Незакомічений `page.html` (+175/−39) змішається з перебудовою, якщо F0.1 не
  зробити першим.
- Розділення файлів ламає шість текстових перевірок `test_page.py` та
  i18n-екстрактор одночасно — це має бути один коміт із `make i18n`.
- `container-type` на `#chat` робить його containing block для `fixed`:
  `#pinpreview`, `#sheet`, `#toast`, `#veil` мусять лишитися поза `#chat`.
- Переїзд `#stage` ламає `vars()` і `restyle()`; id має жити, доки `#live` не
  переїде в стрічку.
- Позиційні id пінів тримаються на append-only `turns.jsonl`; компакція сесії
  зсуне id.
- Два екземпляри `PinStore` на одному файлі затирають один одного; творець
  один, fallback лише для тестів.
- Живі віджети перезапускаються під час переїзду; стан iframe втрачається.
- Спрощені шити макета (джерела, копії, профіль) — найбільший ризик втрати
  даних; тому L3 — restyle, не порт.
