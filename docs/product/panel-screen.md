# Екран плати як фреймворк

*26 жовтня 2026. Що вміє екран плати і як він влаштований — одна модель
замість розрізнених «показати слова», «картинка», «обличчя», «ALLOW». Плата:
ESP32-C3, OLED 72×40, 1 біт, MicroPython. Скіли й руки — [hands-infra.md](hands-infra.md).*

## Чому

Зараз на екрані живуть п'ять окремих речей, кожна зі своїм кодом і своїм
`if` у головному циклі: обличчя, слово стану (`WIFI`, `PAIR`…), ALLOW,
слова від агента, картинка від агента. Шосте (анімація, годинник, прогрес)
означало б ще один `if`. Натомість — **одна модель**: усе, що на екрані, —
це **сцена** з **віджетів**, а що саме видно — вирішують **шари**.

## Модель

```
ШАРИ (вищий перекриває нижчі)        СЦЕНА = розкладка + віджети + поля
 1. system   ALLOW, PAIR, WIFI, ERROR    ┌──────────────────────────┐
 2. flash    від агента, на N секунд     │ row: [clock]   [icon sun]│  ← розкладка
 3. pinned   від агента, доки не зніме   │ big: {temp}°             │  ← поле {temp}
 4. idle     екран спокою (збережений)   │ bar: {progress}          │
 5. face     обличчя (вбудована сцена)   └──────────────────────────┘
```

- **Сцена** — опис екрана: розкладка, віджети в ній, і **поля** — іменовані
  значення (`temp`, `progress`, `title`), до яких віджети прив'язані.
- **Оновлення** змінює поля, а не сцену: `update(scene, {"temp": 22})` —
  плата перемальовує лише те, що від поля залежить.
- **Анімація — властивість віджета**, а не окрема річ: блимати, пульсувати,
  прокручувати довгий текст, плавно лічити до нового числа, крутити кадри.
  Плата веде її сама, на своєму такті (100 мс), — мозок і руки не шлють кадрів.
- **Шари.** Видно найвищий непорожній шар. ALLOW завжди перший; закріплена
  сцена не губиться від швидкої — повертається, коли швидка минула; екран
  спокою — замість обличчя, коли heare нічого не робить. Обличчя — теж
  сцена (вбудований віджет `face`), тож у спокої можна «обличчя + годинник».

### Розкладка

Екран крихітний, тому розкладка проста — рядки й колонки з вагами, без
абсолютних координат (модель погано рахує пікселі):

```json
{"rows": [
  {"h": 1, "cols": [{"w": 2, "widget": "clock"}, {"w": 1, "widget": "icon", "name": "sun"}]},
  {"h": 2, "widget": "number", "bind": "temp", "unit": "°"}
]}
```

Плата сама ділить 72×40 за вагами, з відступом 1 px. Помилки розкладки
(не вміщається, забагато віджетів) — відповідь скіла з причиною, модель
виправляє.

### Віджети (перший набір)

| Віджет | Що | Поле | Анімація |
|---|---|---|---|
| `text` | рядок або кілька; розмір 1 чи 2 | так | прокрутка довгого, блимання |
| `number` | велике число з одиницею | так | лічба до нового значення |
| `icon` | вбудована іконка з набору (~20) | так (ім'я) | блимання, пульс |
| `image` | картинка (SVG → пікселі руками) | — | кадри (кілька SVG) |
| `bar` | смужка 0–100 | так | плавна зміна |
| `spark` | міні-графік з останніх значень | так (додає точку) | — |
| `clock` | годинник плати | — | двокрапка блимає |
| `face` | обличчя heare | стан heare | своя |
| `spinner` | «працюю» | — | обертання |

Іконки — вбудовані в прошивку (16×16, ~32 байти кожна): серце, сонце,
хмара, дощ, сніг, галочка, хрестик, дзвоник, годинник, лампа, замок, дім,
батарея, Wi-Fi, стрілки, мікрофон. SVG — для всього, чого немає в наборі.

### Шрифт: кирилиця на самій платі

Вбудований шрифт плати — лише латиниця, звідси «Pryvit». Українська — це
~70 гліфів 8×8 = ~560 байт: кладемо свій шрифт у прошивку, і «привіт»
пишеться «привіт». Великі цифри для `number` — масштаб того самого шрифту ×2.

## Скіли — API фреймворку

Усе вище — для рук це п'ять скілів. Старі `show` та `image` лишаються як
скорочення: усередині це сцена з одного віджета на шарі `flash`.

| Скіл | Що | Наслідок |
|---|---|---|
| `screen` | показати сцену: `{scene, layer: flash\|pin\|idle, seconds?}` | harmless |
| `update` | змінити поля сцени: `{id, fields}` | harmless |
| `clear` | прибрати сцену чи шар | harmless |
| `screen_info` | що зараз видно, розмір, віджети, іконки, вільна пам'ять | read |
| `show`, `image` | як зараз (скорочення) | harmless |

- **`render` з шляхом.** SVG у сцені лежить усередині віджетів, тож помітка
  перетворення вчиться шляху: `render: {"scene.rows[*].cols[*].svg": …}`.
  Руки обходять шлях і малюють кожен SVG; плата отримує пікселі.
- **Опис для моделі** — в `about` і `params` самих скілів: модель отримує
  схему сцени, список віджетів і іконок. Окремих інструкцій у руках немає.
- **`idle` зберігається** у флеші плати: екран спокою переживає
  перезавантаження. `flash` і `pin` — ні.

## Межі заліза — бюджет

ESP32-C3 з Wi-Fi: вільної пам'яті MicroPython — порядку 100 КБ (виміряємо,
Е0). Тому жорсткі межі, що перевіряє й плата, й мозок (форма скіла):

- сцена ≤ 3 КБ JSON, ≤ 8 віджетів, ≤ 4 шари одночасно;
- картинки в усіх сценах разом ≤ 16 кадрів (360 Б кожен ≈ 6 КБ);
- перемальовка — лише змінених віджетів; повний кадр — лише при зміні шару;
- такт 100 мс як зараз; анімації — без нових виділень пам'яті на кадр.

Плата відповідає `screen_info` з вільною пам'яттю — руки й модель бачать,
що влазить.

## Як це в коді плати

```
heare_panel/screen/
  scene.py    сцена: перевірка, поля, оновлення          (чиста, тести на Mac)
  layout.py   рядки/колонки → прямокутники 72×40          (чиста)
  widgets.py  кожен віджет: draw(canvas, box, fields, t)  (чиста, FakeCanvas)
  layers.py   шари, що видно, що перемалювати             (чиста)
  font.py     кирилиця 8×8, великі цифри                  (дані)
  icons.py    іконки 16×16                                (дані)
main.py       такт: layers.tick(now) → малює брудне
```

Обличчя, слова стану й ALLOW переїжджають у ту саму модель: `face` — віджет,
`WIFI`/`PAIR`/`ALLOW` — сцени шару `system`. Головний цикл перестає знати,
що на екрані.

**Перевірка без плати:** сцени малюються на Mac тим самим кодом у
`FakeCanvas` → еталонні знімки (`tests/firmware/screens/*.txt`, ASCII 72×40)
і `make panel-preview SCENE=…` — PNG сцени до заливки. Віртуальна плата
(`heare-sim`) приймає ті самі скіли й перевіряє ту саму форму.

## Кроки

| # | Крок | Готово, коли |
|---|---|---|
| **Е0** | **Виміряти** пам'ять і час кадру на платі зараз | числа записані тут; бюджет підтверджений або змінений |
| **Е1** | **Рушій:** сцена, розкладка, шари, такт; обличчя, слова стану, ALLOW, `show`, `image` — на ньому, поведінка та сама | еталонні знімки всіх нинішніх екранів збігаються; `if` про екран у `main.py` немає |
| **Е2** | **Віджети** `text`, `number`, `icon`, `bar`, `clock`, `spinner` + кирилиця | знімки кожного; «привіт» кирилицею на платі |
| **Е3** | **Скіли** `screen`, `update`, `clear`, `screen_info`; `render` з шляхом у руках | «покажи погоду: сонце і 21°» → сцена на платі; `update` міняє лише число |
| **Е4** | **Анімація:** блимання, пульс, прокрутка, лічба, кадри | знімки по кадрах; пам'ять не росте за хвилину анімації |
| **Е5** | **Екран спокою:** `idle` зберігається, годинник (час з мережі) | після перезавантаження — той самий екран спокою; годинник точний |
| **Е6** | **Попередній перегляд:** `make panel-preview` і стенд | сцена → PNG на Mac; стенд проганяє скіли сцен через віртуальну плату |

Кожен крок — тести, стенд, заливка, живий прогін фразами.

## Чого не робимо

- Не шлемо кадри з Mac: анімацію веде плата.
- Не даємо абсолютних координат моделі: лише рядки, колонки, ваги.
- Не тягнемо HTML/CSS: на 72×40 це зайве і не влізе.
- Мозок не знає сцен: перевіряє форму скілів, як для будь-якої частини.

## Відкрите

1. **Хто ставить екран спокою?** Агент сам (`idle` — harmless), чи лише
   коли ти прямо попросив? Пропоную: harmless, бо це лише екран і його
   легко змінити.
2. **Поля, що оновлюються самі** — погода з `sources`, прогрес справи
   opencode. Перший варіант: агент оновлює, коли його просять. Пізніше —
   підписка поля на подію мозку (прогрес справи вже йде в подіях). Окремий
   крок після Е6?
3. **Іконки** — чи є, що обов'язково має бути в наборі?
