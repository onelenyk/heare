# Налаштування: одна команда і локальна форма

*18 жовтня 2026; стан звірено 28 жовтня. Дизайн, узгоджений з господарем.
Тепер у коді: `install.sh`, форма наглядача (`heare-keeper`) і Docker.*

**Стан 28.10:** інсталятор — код: `install.sh` ставить колеса, пише роль
(`all`, `brain`, `body`; `mac` = `all`, `server` = `brain`) і піднімає
служби; форму віддає наглядач
(`packages/heare-keeper/heare/setup.py`) лише на `127.0.0.1`; мозок
збирається в Docker. Форма питає роль: усе тут, тіло або лише мозок.
Тунелю, домену й TLS у коді немає.

## 1. Мета

Одна команда ставить колеса; **усе інше — у формі**: роль машини, частини,
адреса мозку, код, ключі. Форма існує тільки коли потрібна і гасне після
успіху.

## 2. Межі

**Входить:** `install.sh` (колеса й роль), сервер форми в наглядачі, форма,
`config.toml`, обмін коду на токен, встановлення частин із форми, перевірка
з'єднання, відновлення після збою.

**Не входить:** авторизація браузера (окремий крок — сесії; форма лише
*споживає* код), тунель і домен (Ф6), `.pkg`/`.app`, мобільний застосунок
(Ф5).

## 3. Учасники

| Компонент | Роль |
|---|---|
| `install.sh` | uv + ядро + наглядач + **усі колеса, які вміє ця система**; запам'ятовує шлях; запускає форму |
| `heare-keeper` | тримає частини; **сервер форми** (лише stdlib `http.server`, bind `127.0.0.1`); виконує дії форми |
| форма | `127.0.0.1:<порт>`: поля, перевірка, кнопки, стани |
| `config.toml` | `url`, `api_port`, ключі — **одне місце для всієї машини** |
| частини | читають `url` + свій токен при старті |
| мозок | `heare-brain code` — одноразовий код; `/api/pair` — обмін на токен |

## 4. Потоки

### A. Перша машина — мозок тут

```
install.sh → форма
  Роль: усе тут (all) — мозок тут
  Частини: ☑Голос ☑Очі ☑Джерела ☑Руки CLI ☑Нативні руки
  Ключі: DeepSeek, Groq
  [ Підключити ]
     ↓
  наглядач: ставить мозок і обрані частини (з коліс)
  пише config.toml, маніфести
  піднімає launchd/systemd
  перевіряє двері 127.0.0.1:api_port
     ↓ ✅ форма гасне
```

### B. Друга машина — тіла

```
install.sh → форма
  Роль: тіло (body)
  Адреса: https://heare.onelenyk.dev
  Код: 8 символів (з консолі мозку: heare-brain code)
  Частини: ☑Голос ☑Очі ☑Джерела ☑Руки CLI ☑Нативні руки
  [ Підключити ]
     ↓
  обмін коду → токен машини (~/.heare/machine/machine_token, 0600) + `url`
  ставить частини; кожна стукає токеном машини → свій токен
     ↓ ✅ форма гасне
```

### C. Телефон — вікно (після Ф6: домену й TLS ще немає)

```
браузер → https://heare.onelenyk.dev
  → екран «підключити» → код із консолі мозку (heare-brain code)
  → cookie-сесія → вікно
```

Без інсталятора. Кожен браузер — своя сесія.

### D. Збій зв'язку

```
частина не достукалась 3 спроби
   ↓
наглядач піднімає форму знову
   ↓
форма показує: «мозок не відповідає», «код прострочений», «не знайшов адресу»
   ↓
виправив → ✅ форма гасне
```

### E. Переконфігурація

```
heare-keeper setup   → форма з поточними значеннями (адреса, частини)
```

Без переустановки.

## 5. Форма

### Поля

| Поле | Коли | Перевірка |
|---|---|---|
| Роль машини | завжди | усе тут (`all`) / тіло (`body`) / лише мозок (`brain`) |
| Частини | завжди | хоча б одна, якщо не мозок; список фіксований: Голос, Очі, Джерела, Руки CLI, Нативні руки |
| Адреса мозку | якщо «тіло» | `http://` або `https://`, доступність |
| Код | якщо «тіло» | 8 символів, обмін |
| Ключі (DeepSeek, Groq) | якщо не «тіло» | непорожні або пропустити |
| Порт мозку | якщо мозок або усе | 1–65535, вільний |

Публічна сторінка (`site/install.html`) показує ті самі три ролі й п'ять
частин. Для тіла вона показує адресу мозку й код і додає `--url` та `--code`
в команду лише тоді, коли обидва заповнені, а код має рівно 8 символів;
інакше копіювання вимкнено й сторінка каже, чого бракує.

### Стани

`порожня` → `перевіряю` → `✅ з'єднано` (гасне) або `❌ причина` (лишається,
поля збережені).

## 6. Протокол форми

| Метод | Що |
|---|---|
| `GET /` | HTML форми |
| `POST /setup` | `{brain_here, parts, url?, code?, keys?, port?}` → дії |
| `GET /status` | `{state: idle/installing/checking/done/failed, detail}` |
| `POST /close` | закрити форму (тільки після успіху) |

Форма говорить **лише з наглядачем** на `127.0.0.1` — назовні її не видно.

## 7. Код і токени

```
heare-brain code
  → код 8 символів, 5 хвилин, одноразовий; 10 спроб за хвилину з однієї адреси
  → мозок зберігає лише SHA-256 + TTL (~/.heare/machine/pair_codes.json)

POST /api/pair {code, kind: machine|window}
  → 256-бітний токен; мозок зберігає лише SHA-256
  → machine: ~/.heare/machine/machine_token (0600)
  → window: HttpOnly cookie
```

Правило: **майстер-ключ не покидає машину мозку ніколи**. Код — це
«перепустка», не ключ.

## 8. Конфіг

```toml
# ~/.heare/settings/config.toml
url        = "https://heare.onelenyk.dev"  # немає = 127.0.0.1:api_port
api_port   = 9790                          # двері НА ЦІЙ машині (мозок)
setup_port = 9791                          # форма (можна не вказувати)
```

`url` — це адреса мозку, на яку дивиться тіло; публічної адреси в налаштуваннях
немає.

## 9. Життєвий цикл форми

| Тригер | Дія |
|---|---|
| нема `config.toml` / нема `url` там, де треба | форма при старті наглядача |
| частина не з'єдналась 3 рази | форма знову |
| `heare-keeper setup` | форма вручну |
| успіх | сервер форми **зупиняється**, наглядач далі тільки стежить |

Порт зайнятий → форма бере наступний вільний і друкує адресу в термінал.

## 10. Помилки

| Що сталось | Що каже форма |
|---|---|
| DNS / нема інтернету | «не знайшов адресу» |
| 401 | «код невірний або прострочений — візьми новий: `heare-brain code`» |
| TLS | не перевіряється: TLS у heare немає (Ф6) |
| 5xx | «мозок відповів помилкою» |
| порт зайнятий | «порт зайнятий — введи інший» |
| колесо не ставиться | «не встановилось: <текст uv>» |

## 11. Безпека

- форма — тільки `127.0.0.1`;
- код — одноразовий, короткоживучий, ніколи в URL;
- токени — файли `0600`, на сервері лише відбитки;
- форма ставить лише **фіксований список** коліс з теки інсталятора —
  жодних довільних команд;
- після успіху форма гасне, HTML без секретів.

## 12. Тести

- `config.toml`: запис/читання/дефолти;
- код: видача, TTL, одноразовість, ліміт спроб, відбиток;
- обмін: невірний код → 401, прострочений → 401, повторний → 401;
- форма: валідація полів (чисті функції);
- інтеграція: фальшивий мозок + наглядач + форма → успіх і кожна помилка;
- живий: `127.0.0.1`, справжній мозок, справжні колеса.

## 13. Відкриті питання

1. **Фіксований `setup_port` 9791 чи випадковий?** — фіксований із фолбеком.
2. **Ключі у формі?** — так, це замінює `--deepseek-key`/`--groq-key`.
3. **Токен машини чи токен на кожну частину?** — токен машини (один обмін),
   потім кожна частина отримує свій при першому стуку.
4. **Що робити з прапорцями `--parts/--url`?** — лишити для автоматизації,
   форма їх не потребує.
5. **Локальний браузер (127.0.0.1) — авто-сесія?** — ні: усі браузери —
   кодом, бо господар хоче все через домен.

## 14. Досяжність: тунель (Ф6)

**Не в коді:** heare не вміє тунелю, домену чи TLS. Єдине, що є, —
`X-Forwarded-Proto: https` робить cookie `Secure`; публічної адреси в
налаштуваннях немає (`url` — це адреса мозку, на яку дивиться тіло).

Мозок слухає `127.0.0.1` (у контейнері — `0.0.0.0`, але порт публікується на
loopback). Назовні його виводить тунель — сама машина дзвонить назовні, портів
не відкриваємо.

### Швидка перевірка (без домену, без акаунта)

```bash
brew install cloudflared
cloudflared tunnel --url http://127.0.0.1:9790
```

Дає випадкову адресу `https://<щось>.trycloudflare.com` — вона живе, поки
живе процес, і змінюється після перезапуску.

*Перевірено 18 жовтня: з цієї мережі `api.trycloudflare.com` недосяжний
(DNS є, TCP — таймаут; `cloudflare.com` і `api.cloudflare.com` при цьому
відповідають). Тобто без-акаунтний тунель тут не піднімається — іменований
(з акаунтом) треба перевіряти окремо, коли буде логін.* Досить, щоб перевірити телефон:
відкрив → екран підключення → `heare-brain code` на Mac → код → вікно.

### Постійна адреса (домен)

```bash
cloudflared tunnel login                     # один раз, у браузері
cloudflared tunnel create heare
cloudflared tunnel route dns heare heare.onelenyk.dev
cloudflared tunnel run heare
```

Конфіг `~/.cloudflared/config.yml`:

```yaml
tunnel: heare
credentials-file: /Users/<ім'я>/.cloudflared/<id>.json
ingress:
  - hostname: heare.onelenyk.dev
    service: http://127.0.0.1:9790
  - service: http_status:404
```

Постійний запуск — `cloudflared service install` (launchd/systemd).

### Чому це безпечно

- Мозок не видно в інтернеті: тунель сам відкриває з'єднання назовні.
- Сторінка віддається **без ключа**: без коду — лише екран підключення.
- API без ключа → 401; токени — HttpOnly cookie / заголовок.
- За тунелем `X-Forwarded-Proto: https` → cookie стає `Secure`.
- Майстер-ключ не покидає машину мозку ніколи.

### Порядок, коли домен з'явиться

1. `cloudflared tunnel login` і `create`, `route dns`.
2. `install.json` не потрібен — тунель ставиться окремо.
3. Відкрити `https://heare.onelenyk.dev` на телефоні, ввести код.
4. За бажанням — Cloudflare Access (тільки твоя пошта) перед мозком.
